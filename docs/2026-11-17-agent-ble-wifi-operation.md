# Agent 蓝牙换网操作

本说明对应录音优先的空闲蓝牙换网原型。设备录音期间不开放管理蓝牙；设备空闲后才可发现。实机已验证双向跨网络切换、一次试连中断电恢复，以及同网络候选的提交前后断电恢复；三组同源 30 分钟录音上传对照已达到预定吞吐阈值；跨网络断电及多轮稳定性仍在验收，不能将本文视为发布完成声明。

设备空闲且没有有效上传时，管理窗口按约 25 秒工作机会和 8 秒广播调度。有效上传可连续使用网络最多 120 秒，上传中发现可能慢于 30 秒；连续 45 秒没有新的服务端确认进展时恢复普通节奏。排空、扫描和认证还需额外时间，因此这些数字不是发现时限承诺。录音始终优先。管理工具显示等待时不能据此判断设备正在录音、上传或离线。三组同源长音频对照的测量结果和适用条件见实机记录。

## 准备

- 使用已制备独立管理身份的设备和该设备对应的管理凭据；当前命令行通过 macOS 钥匙串服务 `meeting-recorder-management`、账户为设备管理 ID 读取凭据。
- 使用 ESP-IDF 5.5.3 的 Python 环境，安装其 provisioning 依赖及 `bleak`。打开电脑蓝牙，确保设备开机、位于附近。目标 Wi-Fi 须为设备可连接的 2.4 GHz 网络。
- 选择稳定保留的本地 SQLite 路径作为 `--store`；它保存非秘密的待查操作 ID 和结果，不保存 Wi-Fi 密码。不要在存在待查操作时换路径或删除该文件。

## 发起换网

在仓库根目录运行，替换设备管理 ID、路径和 SSID：

```sh
python3 firmware/tools/meeting_wifi_agent_client.py \
  --device '<设备管理 ID>' --store '<本地待查数据库路径>' \
  switch --ssid '<目标 Wi-Fi 名称>'
```

程序默认通过终端交互读取密码；自动化调用可在 `switch` 后加 `--password-stdin`，从标准输入读取一行，适合由凭据管理工具通过管道提供。不要将密码写进命令参数或日志。它等待设备空闲、发现并认证设备后提交一次请求。等待或断连不代表设备已收到请求；仅设备查询返回的终态才能表示切换成功或已恢复原配置。目标网络认证或 DHCP 失败时设备恢复原配置；原网络也不可用时设备继续保留离线录音。

当前进程能确定发现或连接在业务数据发送前失败时，会保留同一操作 ID 自动重试；一旦开始发送或状态无法确定，则只查询该操作，避免重复提交。查询或确认期间连接失败会继续显示“结果待确认”。进程重启后不保存也不恢复 Wi-Fi 密码，只能查询已持久化的操作。

## 中断后继续查询

保留同一设备 ID 和数据库，运行：

```sh
python3 firmware/tools/meeting_wifi_agent_client.py \
  --device '<设备管理 ID>' --store '<本地待查数据库路径>' resume
```

程序继续查询同一操作 ID；确认设备已记录终态并完成结果确认后才清除本地记录。收到“结果未知或已过期”时会显示待查操作 ID，并保留记录。明确决定放弃该未知结果时，可在设备附近执行：

```sh
python3 firmware/tools/meeting_wifi_agent_client.py \
  --device '<设备管理 ID>' --store '<本地待查数据库路径>' \
  abandon --operation-id '<显示的待查操作 ID>'
```

该操作会重新认证并查询：只有设备仍返回未知或已过期时才清除对应的本地记录；无法连接、仍在处理中或已出现终态都不会删除记录。它不能推断原操作成功或失败，也不能覆盖设备上未确认的其他事务。再次发起换网将生成新操作 ID。

自动化脚本可检查退出码：换网成功为 0，已回滚为 2，未知或尚未确认的结果为 3，需要维护为 4；显式放弃未知结果完成时为 0。连接或其他执行错误也会以非零退出。

## 维护与限制

管理凭据轮换、撤销和恢复当前使用限目标设备的 USB 维护构建；构建产物包含秘密，须本地保护、完成后刷回普通固件并清理临时产物。远程凭据轮换尚未实现。设备没有启用安全启动和 Flash 加密，此原型不抵御可读取或改写设备 Flash 的人。

完整设计、验收阈值和未完成项见 [空闲换网设计](superpowers/specs/2026-11-16-idle-ble-wifi-switch-design.md)、[上传优先调度修订](superpowers/specs/2026-11-17-upload-priority-idle-switch-design.md)及[实机记录](../research/2026-11-18-idle-wifi-validation.md)。
