# 录音优先的空闲蓝牙换网

## 目标和范围

Agent 在附近免按键为会议录音卡切换 Wi-Fi。录音优先，录音过程中不要求蓝牙可发现或可认证；原网络失败时仍可发起换网，新网络连接失败自动恢复原配置。空闲且设备可达时，以 Agent 发起请求后 30 秒内发现并开始换网为实测目标；录音期间和设备关机期间不计入该目标。此次是单台受控测试设备的初版，不以录音与蓝牙并存为前置条件。

本设计取代 [此前专项设计](2026-11-06-agent-ble-wifi-switch-design.md) 中要求录音期间设备接收请求及优先验证 BLE/STA 并存的内容；其不冲突的事务、身份、异常恢复原则继续适用。不能将尚未开发或验证的功能当成已有能力。

## 方案选择

- **周期性蓝牙窗口（采用）**：空闲期间停止 Wi-Fi 后开放受认证保护的 BLE，关闭后恢复 Wi-Fi 和上传。在线、离线均适用，代价是周期性打断网络。
- 在线时由服务端通知设备开启蓝牙，离线时仍用周期窗口：可减少在线时的中断，但需要新增服务端通知链路，初版暂不采用。

## 空闲窗口与录音

设备无录音、无换网事务时周期调度短暂 BLE 窗口。每个周期先阻止新上传请求，有界取消或等待当前请求，确认相关网络任务和资源已退出，再停止 STA 并开启 BLE。无管理连接时超时关闭 BLE，恢复 STA 和上传。连接建立、认证及事务的超时均有上限，未授权连接不能无限阻止录音或上传。初始周期和窗口长度由实现者选定，需覆盖扫描、连接和认证并经实机调整；不能仅凭定时器宣称满足 30 秒，须计入关闭网络、蓝牙启动、扫描和调度开销。若停止网络超时则跳过窗口并保留录音及上传状态，Agent 明确报告尚未发现设备。

录音请求随时具有最高优先级：禁止启动新窗口；窗口已打开时关闭连接和 BLE、释放录音资源，再开始录音。记录从按键到采集的延迟并设定可验证的实现目标；若无法释放资源或达到目标，明确告知录音启动失败，不假称已录音。Agent 在录音时可能根本无法连接，故由 Agent 本地持续扫描并显示“等待设备空闲或连接”，不能声称设备已收到请求或确定设备正在录音。录音保存后恢复窗口调度。Agent 退出或超时则报告未完成；重启后的继续等待需有可恢复的本地任务，不能假设设备已保存请求。

已认证并收到候选配置后开始换网事务。提交前被录音抢占时，中止连接测试，保留已持久化候选与操作 ID 为等待状态；保存后在新的窗口或设备本地恢复测试。同一 ID 同一请求幂等，内容不同拒绝；最终状态可在重新连接后查询。提交之后开始录音不撤销新网络。录音期间不会自行执行 Wi-Fi 测试或恢复上传。

每次录音启动请求分配单调递增的运行时代次，关闭 BLE、停网络、启动采集及其异步回调都携带该代次；共享资源转移和开始采集前在同一协调锁下检查代次仍为当前且请求有效。超时先原子撤销该代次并显示失败，再允许重试；旧回调只能释放自己仍持有的资源，不能启动采集、改变新请求状态或释放新请求持有的资源。若旧释放尚未完成，新请求等待有界排空；无法确认资源归属时失败关闭，不并发启动。设备重启丢弃所有未完成的运行时请求并从硬件和持久录音状态重建；已成功创建但未封存的录音按既有中断恢复规则处理，不自动把超时请求解释为新录音。

管理窗口按事务阶段调度：等待录音结束时由 Agent 本地等待，设备不开放 BLE；录音保存后若候选待恢复，可优先进行有界候选测试，测试完成或被取消后开放窗口供认证和查询。候选测试及提交期间 STA 使用中不开放 BLE；该阶段的 Agent 显示“结果待确认”并重试，不凭断连判断成败。终态写入持久记录后，无录音时恢复周期窗口，即使结果尚未被查询也继续调度上传；Agent 凭同一设备身份和操作 ID 认证查询。查询可用性受窗口、停网及录音优先约束，并以空闲且网络任务可安全停止时 30 秒内发现为目标；超时显示等待，不能保证绝对时间。

设备至少持久保留最近一次事务的操作 ID、请求摘要和终态 7 天，跨重启可查；七天内新的不同操作不得覆盖未被确认读取的终态，除非 Agent 明确放弃该结果。已确认读取的终态允许在接收新事务时替换；七天到期后可回收，查询返回“结果已过期或未知”，不得推断成功或失败。没有可靠时钟时保守保留至已确认读取或明确放弃；相同 ID 仅在记录存在时保证幂等，过期 ID 不得被 Agent 自动重用。记录损坏或存储不足时拒绝新事务并报告维护，不抹掉不可判定的结果。

## 换网事务与上传

稳定配置与候选配置独立保存并验证；仅修改 SSID 和密码，不改变服务、设备身份、信任锚或时间。完成关联并获得 DHCP 地址才算新 Wi-Fi 连接成功；外网、DNS、服务不可用另行报告，不触发密码失败回滚。认证错误、关联失败或 DHCP 超时则恢复旧配置；旧网络也不可用时离线保留录音并继续提供空闲蓝牙窗口。

配置生效须有单一、可恢复的持久化提交点；候选、提交前后结果、断电及提交结果不明的读取与重试遵循旧设计的双槽和提交指针规则，不能依赖多 key 原子提交。若无法判定唯一生效配置，停止覆盖并进入维护状态。请求结果丢失时通过操作 ID 查询，不能盲目重复覆盖。

暂停上传和换网不得删除本地音频。恢复时按原上传协议查询已确认块并续传；服务端确认丢失时按既有幂等协议核对，不将发送成功等同持久确认。窗口不应使持续上传永久饥饿：每次恢复后应给上传有界的连续工作机会，具体配额以实测同时满足发现目标和吞吐为准；若两者无法兼顾，报告实际表现，不静默降低目标。

30 秒是产品目标而非以反复取消上传硬性保证的期限：慢请求优先在有界时间内安全结束或取消，若释放资源超过窗口预算则跳过窗口，Agent 在 30 秒后显示“仍在等待设备”，持续重试或允许取消；禁止显示已连接或换网已开始。需用真实慢请求验证最终上传完成以及发现延迟，若无法兼顾，作为未达标报告并调整窗口参数或设计。录音启动暂以按键至采集不超过 3 秒作为工程目标（非已有实测），超时明确提示并允许再次尝试；不得无限等待或假装录音已启动。

初版性能验收基准：使用一条 30 分钟录音，记录实际编码字节数；在同一 2.4 GHz 接入点、同一服务和信号位置分别进行无周期窗口的基线上传和启用窗口的上传，各至少三轮并从零开始，确认服务端完整性。启用窗口时单轮完成时间目标为对应基线的 1.5 倍以内且不超过基线加 15 分钟；每轮均须完成，不得因为多次取消而始终无法完成块。窗口间至少提供 20 秒连续上传机会；窗口包含完整的释放、BLE 广播和恢复阶段，参数必须实测能同时达到空闲 30 秒发现目标。另对响应耗时超过 30 秒的真实慢请求测试最终上传完成及超时反馈；慢请求例外不计入普通网络延迟达标样本。记录网络、文件大小、各轮耗时与失败次数，任何阈值不满足均标记未达标，不能用一次完成替代。

## 身份与设备重置

使用此前设计的每设备独立管理身份、认证加密会话、目标绑定和 USB 维护制备；凭据的建立、轮换、撤销、重放与恢复必须实测，固定测试码或 MAC 不能作为正式授权。Agent 保存凭据于系统凭据库，不在日志、仓库中输出凭据。该设备未启用安全启动或 Flash 加密，不声称抵御能读取或改写设备的人。

用户已授权清空重置这台测试设备。实施前先识别目标设备、确认测试录音均可丢弃，准备原固件、分区清单、Wi-Fi 和服务重新制备流程；明确旧设备服务端凭据如何撤销或管理，避免重置留下未管理的有效凭据。为避免旧文件因退休标记被清除而重新上传，清空 NVS 与旧测试录音须作为受控重置流程协调，不能在仅擦除 NVS 后直接启动旧应用并自动上传；中断时保持无法自动上传，直至清理和重新制备完成。重置不构成产品首次初始化或迁移方案。

执行顺序须先通过服务端撤销该设备旧上传凭据并验证拒绝，再进行清空与重新制备；禁止在旧凭据未确认撤销时擦除保存它的设备状态。由服务端撤销提供跨设备断电和旧固件启动仍有效的上传屏障；如果服务端不可达或无法验证撤销，则停止重置。清理旧录音完成并核对后，才建立新身份和上传凭据；不得恢复含旧身份的 NVS 备份或未清空录音的旧分区。上述针对本台测试设备，不作为通用恢复机制。

## 可见反馈与验收

Agent 展示等待设备空闲或连接、正在认证、正在切换、成功、失败已恢复和需要维护；只有真实得到结果才显示成功。设备在可显示时给出简短状态，不显示密码。设备没有连接时不得臆测其录音状态。

1. 在原 Wi-Fi 在线、离线和上传中分别发起换网，多次测量从请求到发现及换网开始的耗时，验证 30 秒目标、窗口占空、上传吞吐与无饥饿；未达目标如实报告。
2. 录音中发起请求、窗口开启时开始录音、认证和新网验证中开始录音，检查响应时延、采集完整性、已保存数据和事务恢复；包括超时立即重试、旧 BLE 退出迟到、新旧请求事件交错及重启，证明旧代次不能启动采集或覆盖新状态。
3. 验证旧网络恢复、新网无外网、认证失败、错误密码、无 DHCP、网络任务停止超时、NVS 空间不足和写入不确定；覆盖每个提交阶段断电及响应丢失，确认唯一生效配置和查询结果。
4. 以真实服务验证分块上传暂停、重连和最终确认，核对完整性及设备仅在确认后清理；测试重复请求和上传与录音抢占交错。
5. 验证目标设备绑定、跨设备凭据拒绝、轮换撤销、重放和凭据恢复，记录重置前后的服务身份与旧凭据状态。测试等待、测试及提交阶段断连，以及 ACK 丢失、重连查询、未读取结果禁止覆盖、结果过期和无可信时钟保留。分别报告主机、构建、实机及未验证项；认证、录音和上传稳定性须经多轮实测，不能从单次探针推断。
