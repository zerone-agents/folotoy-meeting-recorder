# Agent 蓝牙换网设计

## 目标与范围

Agent 无需用户按设备按键，向已配置、正在联网或离线的会议录音卡发起 Wi-Fi 切换。新网络连接失败时自动恢复原网络；换网不改变会议服务地址、设备凭据、CA、可信时间状态或录音数据。当前目标为这台受控测试设备的原型；不把现有固定测试配对码、MAC 或普通 Flash 当成正式的抗篡改设备身份。

## 方案与选择

选择附近 Agent 通过 BLE 发起换网。另一方案为服务端在线下发，但原网络不可用时设备无法收到命令，因此不满足当前场景。设备须在网络任务运行或断网期间提供可发现的管理入口；能否在 ESP32-C3 上与 Wi-Fi、录音任务共存、是否需要先停 Wi-Fi 后启动管理 BLE，均须通过实机构建、内存和并发测试验证，不能将现有首次配网接口直接视作已支持。

沿用现有认证加密的 BLE 会话协议，新增明确的换网操作，仅接收 SSID 和密码，不接受静默修改服务地址、信任锚、凭据或时间。测试原型的自动认证和设备识别遵循当前受控设备方案；正式交付前另行完成无需人工操作的设备身份和认证设计。设备与 Agent 均不得在日志、响应或仓库输出密码或密钥。接收、候选持久化、连接验证、配置生效是不同状态，不能把现有首次配网的持久化 ACK 当成换网成功。Agent 选择唯一目标并使用会话绑定操作 ID；多设备或认证失败时拒绝，不向不确定目标发送凭据。

## 实施门槛：无按键唤醒与身份

现有 `meeting_pairing_ble_start` 明确拒绝 STA 运行，这是当前实现的限制，并非新方案必须遵守的硬约束；允许在隔离原型中验证管理 BLE 与 STA 并存，但只有资源、录音和上传等实机验收通过才可采用。当前设备既没有已验证的并存管理 BLE，也没有可由 Agent 调用的停网唤醒通道。因此“蓝牙换网”是目标而非已证实的入口；不得基于假定并存直接实现完整事务。先做独立、可回退的实机可行性验证，固定固件版本和设备，分别覆盖：原 Wi-Fi 在线且正在上传、原 Wi-Fi 不可用、录音中及空闲。验证必须证明 Agent 能发出第一个受授权信号、设备能接收并响应，且录音和上传未受不可接受的干扰。观察堆内存峰值、最大连续空闲块、音频丢帧及上传中断与续传，记录配网入口的可发现性和资源限制。

候选入口依次验证：(A) 独立管理 BLE 与 STA/现有蓝牙并存，使用认证管理会话接收命令；(B) 若 A 不可行，只能选经过实机验证、在旧 Wi-Fi 在线及失效两种情形都可接收的独立唤醒通道，再有界停止上传网络并开启认证 BLE。在线服务端命令只能作为在线辅助，不能充当离线入口；周期性无条件停网打开 BLE 不能声称零影响，也不能在缺少明确时隙与影响验收时作为完成方案。任一路径未满足目标时停止后续实施，报告实测限制并与用户调整需求，不能凭推测继续。

本阶段认证契约是**单设备受控原型**，正式安全能力另行设计。每台设备建立独立、高熵随机管理凭据和稳定管理身份；首次建立通过 Agent 持有的、物理直连的 USB 制备通道完成，并核验目标设备与写入后回读结果，不借助设备显示的配对码或按键。管理凭据与现有上传设备令牌分离；Agent 保管在本机系统凭据库或等效受保护存储，不提交仓库、明文日志或常驻临时文件。BLE 使用基于该设备专属凭据的 Security 2 双向认证、会话加密与新鲜握手；只有认证成功且目标身份绑定后才能发出换网。操作 ID、会话绑定、事务代次及消息顺序共同限制重放；不接受仅凭设备名、MAC 或统一固定码授权。上述握手、绑定和重放保护须经实际协议和故障测试证明，不能只因使用 Security 2 即视为完成。

支持经已授权的管理身份轮换或撤销 Agent 凭据：先持久化新凭据或撤销代次并读回，再确认变更；设备重启后旧凭据不能恢复。凭据丢失时，不允许通过未认证 BLE 接管；通过物理 USB 维护流程重新制备并撤销旧凭据，保留原网络、服务身份、录音和上传数据。设备重置须明确区分网络/管理凭据重置与存储擦除，不能以缺失 NVS 为格式化许可。由于当前设备未启用安全启动和 Flash 加密，能改写固件或读取 Flash 的人仍可能窃取或替换凭据；该方案不声称抵御物理攻击，正式产品须另行确定硬件信任与恢复机制。

## 状态与持久化

- 操作状态：空闲、等待录音结束、暂停上传、待验证、测试新网络、已切换、已回滚或需维护。Agent 可查询操作 ID 的状态，重复提交相同操作 ID 和相同内容是幂等的；相同 ID 携带不同内容必须拒绝。设备只允许一个换网事务，事务代次用于拒绝旧会话或迟到结果覆盖新事务；重启后仍能查询最终结果；比较使用已受保护的候选配置，不额外保存或记录明文密码。
- 原配置保持为已提交的稳定版本。新配置作为独立候选记录持久化并读回校验，不能在验证前覆盖原配置；现有首次配置接口明确拒绝不同 SSID 或密码，换网须新增专用事务，不能绕过原有检查；提交前按容量检查 NVS，空间不足或读写异常时停止并保留原配置，返回明确错误。候选记录只允许更改 Wi-Fi 字段；所有身份和安全配置与原版本一致。
- 使用带校验和代次的双槽记录和单独的提交指针（或经验证等效机制），将哪个配置是生效版本的切换作为原子提交点。精确定义写入、同步、读回、指针提交和状态持久化的先后顺序；不能假设多个 NVS key 同时原子提交。异常或写入结果不明确时重新读取并验证；若无法判断唯一有效配置，停止自动上传和覆盖，保留原数据并进入维护状态。
- 新网络成功定义为设备完成 Wi-Fi 关联并获得 DHCP 地址；使用有限且可配置的测试时限。外网、DNS 或服务不可达不等同 Wi-Fi 密码错误：成功切换后分别报告服务状态，按现有机制重试，不因暂时无外网回滚网络。连接失败或超时，在不删除原配置的前提下停止候选连接、清理候选秘密并恢复原网络；原网络也不可用时继续离线保存录音和按原配置重试，提供蓝牙重试入口。
- 启动时先恢复换网事务并确定有效配置，再运行现有 `meeting_restore_start`；不能先加载旧 `active` 记录启动网络后才处理事务。ESP-IDF 当前使用 RAM 保存 STA 配置，不承担持久化回滚。
- 在候选测试或候选持久化后、提交指针前断电：重启选择上一次已提交的原配置并记录事务中断；提交指针及目标槽均经验证后断电：重启选择新配置并完成清理。指针写入结果不明确时按持久化证据确定结果；决不凭客户端是否收到成功响应判断配置已生效。旧槽在新槽、提交指针和结果记录可靠后才可清理；断电中断清理可幂等续做。

## 录音和上传优先级

录音时接受换网请求并显示等待，直到录音停止并安全保存；不暂停或结束录音。提交点之前测试网络时若用户开始录音，立即请求取消候选测试，完成有界停网和音频资源释放后开始录音；事务持久化为“等待录音结束”，保留候选，Agent 查询到待恢复而不是成功。录音安全保存后，若候选仍有效则以同一操作 ID 自动重新进行一次完整关联和 DHCP 验证；重复同 ID 同内容只返回当前状态，不并发重试。候选测试的单次超时仅计测试运行时间，录音期间不计入；若候选在等待期间失效，或重试失败/超时，则回滚原配置并记录失败原因。提交点之后录音抢占不能撤销已经生效的新配置；查询返回已切换，录音结束后在新网络恢复上传。若无法在录音启动时限内停网，按现有录音启动失败路径明确提示，不能声称录音无丢帧。不能在中途改变会议录音状态或格式化存储。

上传中发起换网时先阻止新上传请求，取消或等待当前有界请求并确认网络任务停止，再测试新网络；停止请求为异步操作，必须等到停止完成，超时则保留原配置与录音并报告失败。已确认块使用原有幂等协议查询及续传；无法确认请求结果时保留本地录音，不凭发送成功删除。切换失败恢复原网络后继续上传；成功后使用新网络继续上传。

## Agent 与可见状态

Agent 能发现目标、提交配置、查询阶段及最终结果，无需人工读取配对码、核对证书或按键。仅在实测确有不可替代的物理连接或刷写步骤时告知用户。设备显示简短状态：等待录音结束、正在切换、切换成功、切换失败已恢复或需要维护；不显示密码。若 ACK 丢失，Agent 以操作 ID 查询结果，不重新盲目覆盖配置。

## 验收

1. 实机在原 Wi-Fi 正常、原 Wi-Fi 不可用两种情况下，无按键从 Agent 切换到指定 2.4 GHz Wi-Fi，确认新 SSID、DHCP 和原设备凭据；网络重启后仍连接新 Wi-Fi。服务可用时验证自动上传，另测新 Wi-Fi 无外网仍保留新配置和待上传录音。
2. 密码错误、SSID 不存在、DHCP 超时、服务不可达分别测试；前几项自动回退原网络，服务不可达只报告并重试。验证原网络也不可用时仍可离线录音与重新发起换网。
3. 录音中发起、网络测试中开始录音、反复切换、上传块/最终确认交错，检查录音无丢帧、数据不丢失、上传可续传；异常路径不能错误清理未确认文件。
4. 在候选写入、同步、读回、网络测试、提交指针写入前后、结果保存和旧槽清理各阶段注入断电；检查恢复配置唯一、状态可查询、结果与实际活动配置一致。覆盖 ACK 丢失、重复操作 ID、重复消息、认证失败、多设备歧义、网络任务停止超时、NVS 空间不足和记录损坏。
5. 测试每设备凭据制备、跨设备凭据拒绝、撤销和轮换后旧凭据失效、重放、掉电后撤销仍有效、凭据丢失后的 USB 恢复及不擦除录音。测量正常录音/上传与管理 BLE 共存的内存、启动时延和稳定性；记录具体设备、固件版本与边界。分别报告主机测试、构建、设备测试与未覆盖范围。
