# 企业微信机器人会议纪要推送设计

日期：2026-11-10

状态：复审通过，实施语义已补齐

## 目标

在现有会议纪要订阅体系中支持企业微信群机器人。管理员直接添加机器人后，每份新完成的会议纪要都会生成分享链接，并以企业微信卡片推送到对应群聊。

本期同时提供不含真实会议内容的测试推送，帮助管理员验证 Webhook 配置。

## 已确认的方案

采用统一订阅、按渠道转换消息的方案：

- 普通 Webhook 继续使用现有匿名申请、管理员审批流程。
- 企业微信机器人只能由管理员直接添加，无需申请审批。
- 两种渠道共用分享配置、持久化投递事件、重试、撤销和投递记录。
- 投递前按渠道分别生成普通回调 JSON 或企业微信 `template_card`。

不采用独立企业微信投递系统，避免重复实现分享配置和可靠投递机制。

## 非目标

本期不实现：

- 扫码授权或一键安装企业微信应用。
- 企业微信第三方应用、服务商应用或 OAuth 授权。
- 添加窗口内的图文教程或“打开企业微信”入口。
- 在机器人消息中发送纪要正文、摘要或待办。
- 在机器人消息中额外发送下载地址。
- 编辑已保存机器人的 Webhook；地址变化时撤销旧机器人并重新添加。
- 多实例部署；限流设计沿用当前单实例 SQLite 服务边界。

## 架构与组件

### 订阅渠道

为 `meeting_subscriptions` 增加 `channel` 字段：

- `webhook`：现有普通订阅，数据库迁移时作为默认值。
- `wecom`：企业微信机器人，只能由管理员创建，创建后状态直接为 `approved`。

企业微信复用现有字段：

- `name`：管理员设置的机器人名称。
- `callback_url`：企业微信机器人 Webhook。
- `share_days`、`include_transcript`、`allow_download`：分享配置，含义与普通订阅一致。
- `callback_token`：企业微信渠道不使用。

新增 `wecom_rate_limits` 表，以 Webhook 的 SHA-256 哈希为键保存 `next_allowed_at`。按 Webhook 而不是订阅 ID 限流，既可覆盖尚未保存的测试，也可防止同一机器人被重复添加后绕过额度。数据库不额外保存 Webhook 明文，普通 Webhook 不使用该表。

### 消息适配器

将消息构造和发送按渠道拆分为清晰边界：

- 普通 Webhook 适配器保持现有回调 JSON 和可选 Bearer 令牌行为不变。
- 企业微信适配器负责生成 `template_card`、发送请求并解释企业微信业务响应。
- 投递协调器负责分享与载荷固化、事件状态、限流、重试、终态失败、撤销和安全错误记录，不包含企业微信消息格式细节。

### 数据流与配置语义

1. 新纪要发布时，为当时所有 `approved` 订阅创建持久化投递事件，不补发批准或添加前的会议。
2. 首次投递尝试时，按订阅当前配置创建分享，并把分享地址和完整渠道载荷固化到该事件。
3. 后续重试必须复用首次固化的分享地址和完整载荷，不重新创建分享，也不重新渲染卡片。
4. 因此，配置修改只影响尚未进行首次投递尝试的事件及未来事件；已经开始投递的事件不受后续配置修改影响。
5. 普通 Webhook 和企业微信采用相同的载荷固化语义，避免响应丢失后用不同链接重复通知。
6. 测试推送不创建分享链接，不生成正式投递事件。

分享创建与载荷固化必须在同一数据库事务中完成。若进程在固化后、发送前崩溃，恢复后的首次实际发送仍使用该载荷。

事件载荷包含分享凭证，只允许保留在未完成投递所需期间：

- 可重试事件保留固化载荷。
- 送达或进入终态失败时清除固化载荷。
- 已生成分享自身仍按原有权限和有效期工作；清除投递载荷不等于撤销已发出的链接。
- 备份和日志不得额外输出载荷中的分享凭证或 Webhook。

## 管理接口

### 创建企业微信机器人

`POST /admin/subscriptions/wecom`

请求包含：

```json
{
  "name": "产品群机器人",
  "callbackUrl": "https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=凭证",
  "days": 7,
  "includeTranscript": false,
  "allowDownload": false
}
```

接口要求管理员认证，校验成功后直接创建 `approved` 订阅。响应不返回完整 Webhook。

### 测试未保存的 Webhook

`POST /admin/subscriptions/wecom/test`

请求仅包含 `callbackUrl`。接口要求管理员认证，同步发送测试卡片，不持久化 Webhook。

此接口用于添加窗口中的“测试推送”，避免误点测试就创建正式订阅。该测试与正式消息共用同一机器人限流额度。

### 测试已保存的机器人

`POST /admin/subscriptions/:id/test`

接口要求管理员认证，只允许 `wecom` 渠道。它使用已保存的 Webhook 发送同一测试卡片，不写正式投递记录，并占用该机器人的限流额度。

### 测试响应

- 成功：HTTP 200，`{ "ok": true }`。
- 输入无效：HTTP 400，`{ "ok": false, "error": "invalid" }`。
- 限流：HTTP 429，`{ "ok": false, "error": "rate_limited" }`，不发送测试消息。
- 上游失败：HTTP 502，`{ "ok": false, "error": "安全错误码" }`。

### 现有接口

现有订阅列表、分享配置修改、撤销和投递记录接口继续复用，并增加 `channel` 字段。

普通订阅的回调地址展示行为不变。企业微信渠道只返回不含 `key` 的地址预览，任何读取接口均不返回完整 Webhook。

投递记录增加终态失败时间和安全错误码。列表明确区分“待推送”“已送达”和“终态失败”。

## Webhook 校验

企业微信 Webhook 必须同时满足：

- 协议为 HTTPS。
- 主机名严格等于 `qyapi.weixin.qq.com`。
- 路径严格等于 `/cgi-bin/webhook/send`。
- 查询参数只有一个 `key`，其值为 16–128 个字符，且仅包含英文字母、数字、下划线或连字符。
- 不包含用户名、密码、fragment 或其他查询参数。

测试和保存使用同一校验逻辑。

## 管理界面

在“订阅管理”顶部增加“添加企业微信机器人”按钮。添加窗口包含：

- 机器人名称。
- Webhook 地址。
- 分享有效天数、是否包含逐字稿、是否允许下载。
- “测试推送”和“确认”。“确认”默认置灰禁用，只有当前 Webhook 测试推送成功后才可点击；测试后修改 Webhook 会重新禁用，必须再次测试。

测试成功后仍由管理员点击“确认”，不自动创建订阅。

保存后的机器人出现在现有紧凑订阅列表中，显示“企业微信”渠道标识、脱敏地址、分享配置和投递记录。管理员可以修改分享配置、再次测试或撤销机器人。

终态失败显示安全错误码和失败状态，不再显示为“待推送”。

## 企业微信消息契约

### 正式消息

使用以下完整 `template_card` 结构：

```json
{
  "msgtype": "template_card",
  "template_card": {
    "card_type": "text_notice",
    "main_title": {
      "title": "新会议纪要已生成",
      "desc": "产品周会"
    },
    "sub_title_text": "完成时间：2026-11-10 16:20（UTC+8）\n分享有效期至：2026-11-17 16:20（UTC+8）\n点击查看会议纪要",
    "card_action": {
      "type": 1,
      "url": "https://meetings.example.com/meeting-service/share#分享凭证"
    }
  }
}
```

整张卡片通过 `card_action` 打开本次分享链接。时间按服务所在时区显示，并带 UTC 偏移。

会议名称取自已有会议标题；标题空白或不存在时使用会议 ID。显示前必须：

- 删除 Unicode 控制字符和格式控制字符。
- 把连续空白折叠为一个空格并修剪首尾。
- 按 Unicode 码点最多保留 30 个字符，超出时以单个省略号结尾。
- 清理后为空时回退到会议 ID，再执行相同的长度限制。

不发送纪要正文，不额外暴露下载地址。纪要和逐字稿下载仍遵循分享链接的 `allowDownload`、`includeTranscript` 和有效期约束。

### 测试消息

测试卡片使用相同的 `template_card` 类型和 `card_action.type: 1`，标题明确标注“企业微信机器人测试消息”。卡片跳转服务根页面，不包含真实会议名称、纪要正文、分享令牌或下载地址。

## fragment 跳转验收与回退

分享凭证当前位于 `shareUrl#token`。HTTP 测试替身无法证明企业微信客户端点击卡片时保留 fragment，因此真实客户端验证是上线前的阻断性验收，不得跳过。

使用仅含合成纪要、短有效期、不含逐字稿且禁止下载的分享，在专用测试群验证：

1. 企业微信桌面端点击卡片能打开分享页并显示正确合成纪要。
2. 企业微信移动端点击卡片能打开分享页并显示正确合成纪要。
3. 页面地址中分享令牌不出现在服务访问日志中。

记录客户端平台、版本和验证日期。任一客户端丢失 fragment 或无法显示分享页时，不得上线直接携带 `share#token` 的卡片，也不得把长期分享令牌简单改放到 query。

回退方案采用服务端跳转码：

- 生成高熵随机跳转码，数据库只保存其哈希及对应分享。
- 卡片使用 `/share/redirect/<跳转码>`，不在 query 中携带长期分享令牌。
- 服务端验证后通过 HTTP 303 跳转到 `share#token`。
- 跳转码与分享具有相同有效期，支持群内多人点击，不采用一次性消费语义。
- 分享删除、撤销或过期后跳转立即失效。
- 回退方案仍需重新通过桌面端和移动端真实点击验收。

## 每机器人限流

企业微信同一消息推送最多 20 条/分钟。为避免正式消息、重试和测试共同超限，对每个 `wecom` 订阅采用更严格的固定最小间隔：

- 同一机器人两次实际发送至少间隔 3 秒。
- 正式首次发送、正式重试和测试推送都占用额度。
- 发送前在 SQLite 事务中原子预留下一个时间槽，并持久化 `next_allowed_at`，重启后仍生效。
- 普通 Webhook 不受此限制。

正式事件未到可发送时间时保持待推送，不增加尝试次数，不记录失败，并在下一时间槽投递。

测试推送未到可发送时间时不同步排队，返回 HTTP 429 `rate_limited`，由管理员稍后重试。

## 成功判定、重试与终态失败

企业微信可能在 HTTP 200 中返回业务错误，因此只有同时满足以下条件才算成功：

- HTTP 状态为 2xx。
- 响应 JSON 中 `errcode` 为 `0`。

### 可重试错误

- 网络错误和响应解析失败：`network_error`。
- 请求超时：`timeout`。
- HTTP 408、429 和 5xx：`http_<status>`。
- 企业微信频率限制：`wecom_45009`。

可重试事件沿用现有相同 `eventId`、10 秒超时和指数退避机制，但必须使用首次固化的载荷，并同时遵守每机器人时间槽。

### 终态错误

- 企业微信 Webhook 无效、机器人被移除或停用，包括 `93000`、`93001`、`93004`、`93006`、`93008`、`93019`。
- 空消息及参数错误，包括 `93017` 和其他未明确列为可重试的企业微信业务错误。
- 其他未明确列为可重试的 HTTP 4xx。

终态事件记录 `failed_at` 和安全错误码，停止重试并清除固化载荷，不再持续创建分享链接。终态失败只作用于当前事件，不自动撤销订阅；管理员可修复配置或撤销后重新添加机器人。

所有企业微信错误只记录 `wecom_<errcode>` 等安全错误码，不保存原始错误正文。

## 备份与恢复对账

最新安全库是订阅和投递事件的唯一权威，旧备份不得使已撤销机器人、已取消事件或备份后新增状态回退。

### 模式标记与旧库迁移

- 新增 `subscription_schema=1` 服务元数据标记。
- 表、标记或 `channel` 定义不完整、不一致或损坏时，恢复以 `invalid_subscription_state` 失败关闭。
- 对企业微信功能发布前的旧库，已有普通订阅和事件可按明确的旧版模式迁移为 `channel=webhook`；不得把缺少渠道信息的新格式数据默认为普通订阅。
- 最新安全库不存在订阅模式时，不从备份恢复任何订阅或投递事件。

### 对账规则

恢复时先清除目标库中的订阅及投递事件，再从最新安全库重建：

- 订阅以安全库为准，保留当前状态、撤销时间和分享配置；`wecom_rate_limits` 中的限流时间槽也从安全库重建。
- 备份后撤销的机器人在安全库中为 `revoked`，不得恢复为 `approved`。
- 备份后新增的订阅和事件若已存在于安全库，必须保留。
- 待投递事件以安全库中的当前状态为准；安全库中已取消、已送达或终态失败的事件不得重新排队。
- 可重试事件连同首次固化载荷恢复；没有固化载荷的事件在首次尝试时按当前配置固化。
- 已送达和终态失败事件只保留审计状态，不得含固化载荷。
- 会议已删除或取消的事件不得恢复为待投递。
- 恢复校验所有外键、渠道、状态、时间、错误分类及载荷 JSON；损坏时失败关闭，不跳过单条记录。

恢复过程中的错误不得输出 Webhook、回调令牌或分享凭证。

### 导出备份的秘密处理

采用净化备份策略，明确区分安全库与导出备份：

- 最新安全库是恢复所需的敏感权威状态，可以包含订阅 Webhook、回调令牌、可重试事件的固化载荷及限流状态，并继续受现有私有文件权限和访问控制保护。
- 导出备份允许包含表结构，但不得包含 `meeting_subscriptions`、`subscription_deliveries` 或 `wecom_rate_limits` 的数据行。导出时清除这些表的数据，避免复制订阅秘密和待投递分享凭证。
- 恢复时不得以净化备份中缺少这些记录为由删除安全库状态；订阅、事件和限流状态一律从最新安全库重建。
- 备份校验必须验证这些敏感表为空，防止实现回归后再次导出秘密。

### 分享过期后的重试

事件固化载荷时同时持久化 `share_expires_at`。每次实际发送前检查该时间：

- 当前时间早于 `share_expires_at`：继续按原载荷发送或重试。
- 当前时间达到或晚于 `share_expires_at`：不得发送，记录 `share_expired` 终态、`failed_at` 和安全错误码，并清除固化载荷。
- 过期判定不增加上游发送尝试次数，不创建新分享，不延长原分享有效期。

### 跳转码日志风险约定

跳转码与分享令牌均为单场会议、只读、限时凭证。持有完整 URL 即可访问本来就是分享语义，跳转码不赋予其他会议或管理员权限。

允许跳转码出现在受控的服务访问日志中，这是明确接受的风险；日志仍不得记录分享 fragment、回调令牌或完整机器人 Webhook。该约定不构成安全阻断。

## 测试与验收

新增自动化测试覆盖：

1. 管理接口鉴权，企业微信只能由管理员创建且直接生效。
2. Webhook 主机、路径、查询参数、用户信息和 fragment 校验。
3. 列表及读取响应不泄露完整企业微信 Webhook。
4. 完整企业微信卡片载荷快照、`card_type`、`main_title`、`card_action.type` 和分享链接。
5. 未命名、空白、超长、含控制字符会议名称的清理和回退。
6. 分享有效天数、逐字稿和下载配置正确传递。
7. HTTP 2xx 且 `errcode: 0` 才标记送达；HTTP 200 且业务失败时记录安全错误。
8. 同一机器人第 21 个一分钟内发送被推迟；正式重试和测试均计入限流，重启后时间槽仍有效。
9. 永久错误写入终态失败且不重试；频率限制、网络错误和服务端故障可重试。
10. 首次尝试固化分享与载荷；响应丢失后的重试使用完全相同的链接和消息正文。
11. 配置修改不影响已开始投递事件；送达及终态失败后敏感载荷被清除。
12. 未保存 Webhook 的测试不持久化配置，已保存机器人的测试不写正式事件；两种测试均不创建分享。
13. 撤销企业微信机器人取消未送达投递。
14. 旧库迁移、备份后撤销、备份后新增、待投递事件、已送达事件、终态事件和损坏 `channel` 的恢复对账。
15. 重试期间跨过分享有效期时以 `share_expired` 终态停止，不发送且不增加上游尝试次数。
16. 导出备份中的订阅、投递和限流数据表为空，恢复仍从最新安全库重建这些状态。
