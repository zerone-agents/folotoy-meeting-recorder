# 企业微信机器人会议纪要推送设计

日期：2026-11-10

## 目标

在现有会议纪要订阅体系中支持企业微信群机器人。管理员直接添加机器人后，每份新完成的会议纪要都会生成分享链接，并以企业微信卡片推送到对应群聊。

本期同时提供不含真实会议内容的测试推送，帮助管理员验证 Webhook 配置。

## 已确认的方案

采用统一订阅、按渠道转换消息的方案：

- 普通 Webhook 继续使用现有匿名申请、管理员审批流程。
- 企业微信机器人只能由管理员直接添加，无需申请审批。
- 两种渠道共用分享配置、持久化投递事件、重试、撤销和投递记录。
- 投递前按渠道分别生成普通回调 JSON 或企业微信 `template_card`。

不采用独立企业微信投递系统，避免重复实现分享配置和可靠投递机制。

## 非目标

本期不实现：

- 扫码授权或一键安装企业微信应用。
- 企业微信第三方应用、服务商应用或 OAuth 授权。
- 添加窗口内的图文教程或“打开企业微信”入口。
- 在机器人消息中发送纪要正文、摘要或待办。
- 在机器人消息中额外发送下载地址。
- 编辑已保存机器人的 Webhook；地址变化时撤销旧机器人并重新添加。

## 架构与组件

### 订阅渠道

为 `meeting_subscriptions` 增加 `channel` 字段：

- `webhook`：现有普通订阅，数据库迁移时作为默认值。
- `wecom`：企业微信机器人，只能由管理员创建，创建后状态直接为 `approved`。

企业微信复用现有字段：

- `name`：管理员设置机器人名称。
- `callback_url`：企业微信机器人 Webhook。
- `share_days`、`include_transcript`、`allow_download`：分享配置，含义与普通订阅一致。
- `callback_token`：企业微信渠道不使用。

### 消息适配器

将消息构造和发送按渠道拆分为清晰边界：

- 普通 Webhook 适配器保持现有回调 JSON 和可选 Bearer 令牌行为不变。
- 企业微信适配器负责生成 `template_card`、发送请求并解释企业微信业务响应。
- 投递协调器继续负责分享创建、事件状态、重试、撤销和安全错误记录，不包含企业微信消息格式细节。

### 数据流

1. 新纪要发布时，为当时所有 `approved` 订阅创建持久化投递事件，不补发批准或添加前的会议。
2. 投递器按订阅当时的配置创建分享链接。
3. 普通 Webhook 发送现有 JSON；企业微信发送卡片，整张卡片跳转该分享链接。
4. UI 的分享配置修改只影响之后创建的分享链接，已投递链接不变。
5. 测试推送不创建分享链接，不生成正式投递事件。

## 管理接口

### 创建企业微信机器人

`POST /admin/subscriptions/wecom`

请求包含：

```json
{
  "name": "产品群机器人",
  "callbackUrl": "https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=凭证",
  "days": 7,
  "includeTranscript": false,
  "allowDownload": false
}
```

接口要求管理员认证，校验成功后直接创建 `approved` 订阅。响应不返回完整 Webhook。

### 测试未保存的 Webhook

`POST /admin/subscriptions/wecom/test`

请求仅包含 `callbackUrl`。接口要求管理员认证，同步发送测试卡片并返回 `{ "ok": true }` 或安全错误码，不持久化 Webhook。

此接口用于添加窗口中的“测试推送”，避免误点测试就创建正式订阅。

### 测试已保存的机器人

`POST /admin/subscriptions/:id/test`

接口要求管理员认证，只允许 `wecom` 渠道。它使用已保存的 Webhook 发送同一测试卡片，不写正式投递记录。

### 现有接口

现有订阅列表、分享配置修改、撤销和投递记录接口继续复用，并增加 `channel` 字段。

普通订阅的回调地址展示行为不变。企业微信渠道只返回不含 `key` 的地址预览，任何读取接口均不返回完整 Webhook。

## Webhook 校验

企业微信 Webhook 必须同时满足：

- 协议为 HTTPS。
- 主机名严格等于 `qyapi.weixin.qq.com`。
- 路径严格等于 `/cgi-bin/webhook/send`。
- 查询参数只有一个 `key`，其值为 16–128 个字符，且仅包含英文字母、数字、下划线或连字符。
- 不包含用户名、密码、fragment 或其他查询参数。

测试和保存使用同一校验逻辑。

## 管理界面

在“订阅管理”顶部增加“添加企业微信机器人”按钮。添加窗口包含：

- 机器人名称。
- Webhook 地址。
- 分享有效天数、是否包含逐字稿、是否允许下载。
- “测试推送”和“保存并启用”。

测试成功后仍由管理员点击“保存并启用”，不自动创建订阅。

保存后的机器人出现在现有紧凑订阅列表中，显示“企业微信”渠道标识、脱敏地址、分享配置和投递记录。管理员可以修改分享配置、再次测试或撤销机器人。

## 企业微信消息

### 正式消息

使用 `template_card`，内容包括：

- 标题：“新会议纪要已生成”。
- 会议名称；没有名称时使用会议 ID。
- 纪要完成时间。
- 分享有效期截止时间。
- “点击查看会议纪要”提示。

整张卡片通过 `card_action` 打开本次分享链接。时间按服务所在时区显示，并带 UTC 偏移。

不发送纪要正文，不额外暴露下载地址。纪要和逐字稿下载仍遵循分享链接的 `allowDownload`、`includeTranscript` 和有效期约束。

### 测试消息

测试卡片明确标注“企业微信机器人测试消息”，不包含真实会议名称、纪要正文、分享令牌或下载地址。

## 成功判定与异常处理

企业微信可能在 HTTP 200 中返回业务错误，因此只有同时满足以下条件才算成功：

- HTTP 状态为 2xx。
- 响应 JSON 中 `errcode` 为 `0`。

失败记录安全错误码：

- HTTP 非 2xx：`http_<status>`。
- 企业微信业务错误：`wecom_<errcode>`。
- 请求超时：`timeout`。
- 其他网络或响应解析失败：`network_error`。

不保存企业微信原始错误正文或响应中的敏感内容。正式投递沿用现有至少一次投递、相同 `eventId`、10 秒超时和指数退避机制。测试推送同步返回 `{ "ok": true }` 或安全错误码。

## 测试与验收

新增测试覆盖：

1. 管理接口鉴权，企业微信只能由管理员创建且直接生效。
2. Webhook 主机、路径、查询参数、用户信息和 fragment 校验。
3. 列表及读取响应不泄露完整企业微信 Webhook。
4. 企业微信卡片字段、会议名称回退、时间及分享链接跳转。
5. 分享有效天数、逐字稿和下载配置正确传递。
6. HTTP 2xx 且 `errcode: 0` 才标记送达；HTTP 200 且业务失败时记录安全错误并重试。
7. 未保存 Webhook 的测试不持久化配置，已保存机器人的测试不写正式事件；两种测试均不创建分享。
8. 撤销企业微信机器人取消未送达投递。
9. 普通 Webhook 的申请、审批、消息格式和双下载链接行为保持不变。
10. 全量现有测试及 `git diff --check` 通过。

本地验收使用企业微信 HTTP 测试替身，不依赖真实群聊；只有用户明确提供测试机器人并要求实测时才向真实企业微信发送消息。
