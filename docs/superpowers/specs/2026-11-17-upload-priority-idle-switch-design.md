# 上传优先的空闲蓝牙换网：调度修订草案

## 决策与范围

2026 年 11 月 17 日，用户决定优先保证录音上传速度，允许上传期间蓝牙发现变慢。录音仍然最高优先；空闲时仍支持 Agent 无按键换网。本修订只改变上传与管理窗口的调度和相应验收，继续遵守[既有设计](2026-11-16-idle-ble-wifi-switch-design.md)的录音抢占、认证、双槽事务、断电恢复及确认后清理规则。审核通过后，它将取代既有设计中“上传期间也以 30 秒发现为目标”的要求；设备无有效上传工作时，原有空闲发现目标继续保留。本文是待验证的设计，不表示固件已经支持。

已有两次方向性实测：开启周期窗口的 1800 秒音频从首次快照准备至设备确认约 1970 秒；关闭窗口的另一段 1800 秒音频约 312 秒。两轮音频和固件不同，不能作为严格配对基线，但说明重复中断对当前设备的影响值得优先解决。详细条件和证据见[实机记录](../../../research/2026-11-18-idle-wifi-validation.md)。

## 调度建议

采用两级窗口，初始参数均为工程建议，须实机测量后确定：

- **普通空闲或不能有效上传**：继续采用现有约 25 秒工作机会和约 8 秒未连接广播窗口；原网失效、无 IP、无可信时间、网络或服务失败、待维护文件以及长期无上传进度时均不得无限延迟管理窗口。设备未连接时 Agent 显示“等待设备空闲或连接”，不能推断其正在上传。
- **有效上传**：给上传一次最长 120 秒的连续网络工作机会，再申请排空网络、开放管理窗口。120 秒从进入该次上传优先机会时以单调时钟计，确认新块、切换到下一条录音或收到重复响应均不重置该次上限；上传持续有进展也不能永久饿死蓝牙。一个窗口完成后开启下一次机会。该数值不是发现硬上界：还须计入排空、BLE 启动、广播相位、Agent 扫描和认证；若排空失败或遇到慢请求，不假报可连接。
- **上传完成**：不等待剩余的 120 秒，安全释放上传资源后及时恢复普通空闲窗口；未确认的音频仍保留。正在等待的 Agent 继续扫描。
- **上传中断或停滞**：立即记录失败／离线等状态并切回普通窗口节奏；首次准备与 TLS 可有至多 45 秒的无进展观察期，超时后切回普通节奏。后续反复建立连接或重复读取同一已知块，不得反复刷新进展和重新触发 120 秒优先；只有观察到新的、经服务端确认的上传进展后才重新进入上传优先。45 秒是初始建议，不能以它为由突破录音启动时限。

不能用现有 `MEETING_NETWORK_SYNCING` 或录音数量直接判定有效上传：前者可能在没有待上传文件时出现，后者还包含不可上传或待维护文件。网络 worker 应发布线程安全、带工作代次的状态：准备／上传中、确认进展、完成、暂停、失败或不可用。确认进展必须指同一会议的已确认连续块位置前移，或该会议得到服务端持久化完成确认；重复响应、清单准备和扫描不能冒充进展。丢失响应后重试得到的确认可以推进尚未记录的水位，但同一位置只能计入一次；重启后重新观察已存在的块不自动证明新进展。45 秒观察期从实际开始准备该工作时计起；进入停滞状态后，失败重试、重新连接或更换待维护文件均不得清除停滞状态，只有新的确认进展才可恢复优先。跨任务读取需原子快照，旧代次的迟到事件不能影响新调度；记录和事务本身仍以既有持久化状态为准。

每次上电先按普通节奏调度，不能因为重启而无限延后首次管理窗口；之后只根据本次启动观察到的真实上传工作进入优先模式。设备重启不得删除未确认录音或丢失已持久化的换网事务。录音请求随时中断上述两种节奏：先阻止新网络请求，按既有代次与超时规则安全释放资源，再开始采集；不得等待 120 秒结束。已接收的候选配置、提交后终态及结果查询继续按既有事务规则恢复，不能被上传优先状态吞掉。

## Agent 和用户反馈

管理 BLE 未可达时 Agent 持续扫描并显示等待；上传期间不承诺 30 秒可发现。Agent 不因等待时间猜测设备在录音、上传或离线，更不能假报已收到请求。已有操作的结果丢失时继续按原操作 ID 查询，终态确认规则不变。当前初版不额外增加服务端推送或设备按键入口。

## 验收与证据

1. 主机状态机与并发测试覆盖：上传刚开始、已确认进展、连续积压跨多个文件、重复块响应、长时间无进展、重试风暴、网络不可用／无 IP／时钟失效、上传完成及重启；验证 120 秒上限不会被新块或新文件延长，旧代次事件不能重置新机会。网络排空失败不得启动 BLE 或误删音频。
2. 测试录音在上传机会、网络排空、BLE 广播、认证与换网各阶段抢占，验证采集真实开始、旧事件无效、已确认块和未确认音频保留；录音启动 3 秒目标仍须实测。
3. 同一 30 分钟样本、同一设备、位置、网络和服务下，分别完成无窗口与新调度从零上传至少三轮，记录字节数、确认耗时、最终服务端完整性、周期与重试次数。仍以各轮不超过无窗口基线的 1.5 倍且不超过基线加 15 分钟为工程目标；不得以此前不同样本和不同固件的单轮数据代替。当前已有音频帧提取工具，但安全设备导入和新身份建立尚未完成，多轮对照尚不能算通过。
4. 普通空闲、有效上传、上传即将完成、长期无进展、网络不可用及积压多条录音时分别发起真实 Agent 请求，统计发现、认证和实际开始切换的时间。普通空闲沿用 30 秒目标；上传期间先报告实测分布及最大值，并以建议的 120 秒机会加实际切换开销评估，不能在尚未测量时承诺上限。真实慢请求超过 30 秒、排空超时、蓝牙连接失败及重启恢复均应单独记录。
5. 不同 2.4 GHz SSID 的成功切换、错误密码／无 DHCP 回滚、响应丢失及提交前后物理断电，分别核对生效网络、原操作 ID 的结果查询和未确认音频。若需设备旁操作，在执行前通知用户。

不满足目标时标明实测差距并调整参数或实现；不以设备缓存、模拟传输、单次成功或设计文本替代设备与服务端验收。
