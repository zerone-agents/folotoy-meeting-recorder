# 开发版备份与恢复

备份和安全状态包含敏感元数据，备份还包含录音及纪要，应限制访问并由运维选择加密、保存位置和保留期限。此方案只提供逻辑删除保护，不保证从 SQLite 空闲页、WAL、旧备份或供应商系统中物理擦除内容。

## 安全前提

恢复必须使用**比待恢复备份更新、且包含恢复切换前所有删除和凭据撤销的同一实例数据库**作为安全状态来源。数据库的 `instance_id` 用来防止误用其他实例的状态，但无法证明来源确实是最新版本。若最新状态也丢失或被回滚，无法推断之后发生的删除及撤销；停止恢复并通过其他可信记录核对，不能把旧备份直接投入服务。

必须先停止所有服务和工作器，并从开始恢复直到新库启用期间保持停止；服务进程与恢复工具会对同一数据库使用互斥锁，服务运行时恢复会拒绝执行。锁只覆盖使用该机制且指向同一数据库路径的进程，不能阻止手动操作或对副本的误用；恢复结束后、切换完成前也不可重新启动旧服务。成功返回前会同步输出文件及其所在目录。否则在读取安全状态之后发生的删除或撤销不会进入恢复结果。对外恢复前，应由管理员核验数据库内容和访问权限。不得用普通文件复制覆盖正在运行的 SQLite 数据库或忽略 WAL。

## 创建快照

运行 `node src/backup-cli.mjs SOURCE_DB NEW_BACKUP_DB`；目标及其 `-wal`、`-shm`、`-journal` 附属文件必须不存在，输出目录应由可信管理员独占管理。工具使用 SQLite 一致快照，包含快照时已提交的 WAL 数据，在副本中完成未完成的删除，并校验数据库结构、外键和已确认音频哈希。成功后同步文件及所在目录；失败时移除未完成输出。运行中的新写入若发生在快照之后，不属于该备份。备份需要存放在受保护位置，并按照部署策略加密和管理。

备份不能代替持续保留的最新安全状态；恢复时仍需下文要求的最新墓碑和撤销记录。

签名时间功能会将私钥及签发时间下界保存在同一数据库；数据库、WAL 和备份均应按私钥材料保护。备份会校验签名身份；恢复会使用可信最新安全库中的身份和下界，若最新密钥缺失、损坏、与备份冲突或安全库下界落后于备份则拒绝恢复。当前不支持签名密钥轮换，也不能在最新安全库和备份都丢失较新状态时自动发现回滚。

## 恢复步骤

1. 确认服务和所有工作器已停止，保全最新数据库及其 WAL/SHM；准备可读的旧备份、当前安全状态数据库和一个不存在的输出文件路径；输出的 `-wal`、`-shm`、`-journal` 也必须不存在，输出目录须由可信管理员独占管理。安全状态必须是完整一致的 SQLite 库。
2. 运行 `node src/restore-cli.mjs BACKUP_DB CURRENT_SAFETY_DB NEW_OUTPUT_DB`。该工具不会覆盖已有输出，检查实例身份、最新安全状态和输出库的 SQLite 结构及外键，对照最新安全状态校验已确认录音的块数、大小和哈希及已有转写、纪要版本，升级输出副本的旧版表结构，并在对外提供服务前应用墓碑、撤销记录、最新设备凭据、未确认上传及会议处理状态；运行中的租约会失效并回到队列，有效的纪要批次检查点会保留。如果旧备份缺少已确认录音、录音损坏、缺少已保存的结果版本，或者旧备份中的活动会议在最新安全状态中没有对应记录或墓碑，恢复会失败并移除未完成输出；应选择包含这些数据的备份或从完整的当前数据库建立新的备份。
3. 检查输出和运行日志，按照部署环境安全地切换数据文件，确认原数据库及其 WAL 不会被混用，再启动服务。应按实际部署设计回滚步骤，不直接覆盖唯一的安全状态来源。

恢复工具会从最新安全状态复制未确认上传，但不会自动补齐备份创建之后新增且已确认的录音或其他业务数据，也不能恢复最新安全状态本身；因此备份频率、灾难恢复目标和可信安全状态的独立持久化仍需部署方案确定。当前实现未提供生产级备份管理、自动轮换或多机协调。

会议删除完成后，当前数据库墓碑保留会议 ID、归属和防复活所需状态；录音哈希、大小、时间、结束原因和处理错误等元数据会清空。打开旧版数据库时会清理旧墓碑上的这些字段；从删除前备份恢复时也会应用同样的清理。此逻辑清理不保证从 WAL、旧备份或物理介质上擦除历史数据。

分享恢复以经过校验的最新安全数据库为准，清除备份中的分享并复制尚有效的当前记录；最新安全库中标记和分享表均不存在时，输出 `shareStatus: unverified_invalidated`，所有分享失效。仅缺其中一项、模式不支持或状态无效时恢复失败。必须使用可信的切换前最新安全数据库：同一数据库中的标记不能证明数据库未被整体回滚。旧版本降级可能丢失分享状态，恢复后应重新创建失效链接。
人工编辑的纪要与录音、转录同属敏感业务数据。备份包含编辑；恢复时以可信最新安全状态中的人工编辑及版本为准，并随会议墓碑清除。恢复前仍须保全包含最新编辑的完整安全状态；旧备份不能替代它。

## 订阅与企业微信状态的净化恢复

创建快照时，导出工具会清空敏感订阅状态：`meeting_subscriptions`、`subscription_deliveries` 和 `wecom_rate_limits` 三张表的全部行均不进入备份。因此备份不含 webhook key、回调令牌、冻结卡片正文或分享凭证；这不改变备份中其他录音、纪要和元数据的敏感性。

恢复时以恢复切换前的**最新安全库**为唯一权威来源，而不是以备份中可能过期的订阅状态为准。工具从最新安全库复制当前订阅、投递和共享限速状态；最新安全库没有订阅模式标记时，目标库中的三张表全部净化为空，不能让旧订阅重新生效。已撤销订阅、已送达或终态失败的投递、已取消的待投递事件均保持原状态，不能因使用旧备份而复活；可重试投递沿用安全库中冻结的正文与过期时间。

启动或恢复遇到不受支持的模式标记、损坏的 channel 定义或无效存储状态时必须关闭失败，报 `invalid_subscription_state`；不得猜测为普通 webhook 或企业微信订阅后继续运行。完成恢复后仍须按上文步骤核验输出，并保全最新安全库及其 WAL，旧备份不能替代最新安全状态。
