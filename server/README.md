# 会议录音服务

本服务接收设备上传的录音，保存音频块与处理状态，使用 StepFun 转录并通过 agent-runtime 生成会议纪要，提供管理页面及下载接口。它是单实例 SQLite 原型，尚未完成全面安全审计；实际部署需自行评估认证、HTTPS、供应商数据、备份与保留策略。

## 运行与接口

- Node.js 22.13.0+；在本目录运行 `npm ci` 和 `npm test`。测试需要 FFmpeg/ffprobe、OpenSSL 与可用的本机回环端口。
- 设置 `MEETING_ADMIN_TOKEN`（至少 7 个非空白字符）、不同的 `ZERONE_AGENT_HTTP_API_KEY`（至少 32 个非空白字符）和 `STEPFUN_API_KEY`。默认 HTTPS 模式还需要 `MEETING_TLS_CERT`、`MEETING_TLS_KEY`；通过可信反向代理终止 HTTPS 时可显式设置 `MEETING_HTTP=true`，并把服务限制在本机或可信网络。
- [本机运行](OPERATIONS.md) · [Compose 部署](../deploy/README.md) · [设备与管理 API](API.md) · [备份恢复](BACKUP.md) · [供应商数据](PROVIDER-DATA.md)。
- 设备通过 Wi-Fi 提交录音，确认后服务以 StepFun SSE 和流式接口处理转录，默认使用 `step-3.7-flash` 生成纪要。模型调用可能计费。转录时间为估算，纪要必须人工核对；结果引用匹配不能保证语义正确。

## 已验证与限制

设备直传、单次 30 分钟录音上传、限定故障注入、页面编辑和下载已有记录，见 [设备实测](../research/2026-11-03-agent-commissioning-upload-test.md)与 [ASR 实测](../research/2026-10-30-stepfun-asr.md)。这些不证明任意断电、网络条件或真实多人会议的可靠性与准确率。多人管理员、物理安全删除、证书轮换及供应商和备份数据的生命周期仍需部署者评估。

下面保留的是带日期的历史实现和验证记录；其中的测试数量、环境与“待验证”描述不能替代当前状态。旧版[验收追踪](ACCEPTANCE.md)同样是 2026-10-30 的快照。

2026-10-30：用虚构文本实际调用 agent-runtime 和 `step-3.7-flash`，生成 JSON 通过引用校验；一次小样本不代表真实会议质量。

处理请求默认最多等待 10 分钟，超时后记录失败并按照重试策略重新调度；已丢失租约的晚到结果不会发布。重新转写保留历史版本并清除当前结果，直到新版本生成。SQLite 升级时会回填旧版已有的转写和纪要版本。

当前转录先调用 StepFun `stepaudio-2.5-asr` SSE，再使用 `stepaudio-2.5-asr-stream` WebSocket 获取 VAD 估计分段时间；两路文字经保守的标点及空白归一化后完全一致时使用流式分段；存在少量差异且数字和符号一致时保留 SSE 转录结果作为纪要依据，同时将流式分段单独标注为可能不完整、需要人工复核。差异超出阈值、流式中断或分段异常时不发布结果，并按任务重试策略重新处理。两次调用可能分别计费，须确保密钥对两个接口均有权限；两路一致不能证明两者没有共同遗漏，VAD 起止时间只是估计。历史转录未保存时间时显示时间戳不可用。

开发版接口见 [API.md](API.md)。`MEETING_MINUTES_MODEL` 可覆盖默认 `step-3.7-flash`。长逐字稿按原始片段分批，逐批核验原文引用并拼接结果；它不会自动消除跨批重复或推断跨批上下文，质量仍需真实会议评估。

离线恢复工具及其前提见 [BACKUP.md](BACKUP.md)。必须保留恢复切换前最新的安全状态，不能在运行中直接替换 SQLite 数据库。

`MEETING_RETENTION_DAYS` 可显式设置正整数天数；未设置时不自动删除。启用后只清理完成处理且完成时间超过该期限的会议，并保留删除墓碑；尚在上传、排队、处理或失败的会议不会自动清理，旧数据中没有完成时间的会议也会保留。重新转写会在新纪要完成时重新计算完成时间。管理员可通过 `GET /meeting-service/admin/settings` 查询当前配置。清理只针对当前库的逻辑内容，不包括供应商或历史备份。

本地管理员以独立的 `MEETING_ADMIN_TOKEN` 认证；`MEETING_ADMIN_ID` 可设置撤销事件的审计身份，默认 `local-admin`。这是单管理员本机部署方案，令牌须随机生成并安全保管，不能视为已完成多人身份管理。配套工具尚须实现持久化撤销待办并携带稳定的事件 ID。

管理员可通过 API 查看结构化转写和纪要，并将完整性校验通过的录音导出为 Ogg Opus。服务收到停止信号后不再领取新任务，主动取消当前模型调用并释放租约；供应商可能仍完成和计费，晚到结果不会发布。

可通过 `MEETING_STORAGE_LIMIT_BYTES` 设置服务端音频块的总逻辑字节上限；未设置时不限制。上限覆盖所有设备和未完成上传，达到时返回 HTTP 507；设备应保留录音并稍后重试。此配置不包括数据库索引、WAL、备份或其他文件，不是磁盘配额，实际部署还须预留磁盘空间并监控。

对外 HTTPS 监听器只允许 `/meeting-service` 业务路径，Runtime 内置 `/v1/*` 仅供进程内部使用；对外处理请求最多并发 64 个，超出返回 429，停机时返回 503。该限制是单进程并发保护，并非按客户端限速；如果开放到不可信网络，仍需在可信反向代理处部署限流、连接超时和网络访问控制。所有会议业务响应均禁止缓存。

新工作台支持纪要 Markdown 预览、带版本冲突保护的在线编辑、转录分段及文本下载。已保存的人工编辑与生成结果分开保存在 SQLite；若生成版本变化，页面提示人工编辑基于旧版本。删除会议会清除当前库中的人工编辑，备份及物理存储的限制仍适用。

本机启动后，可在浏览器打开 `https://localhost:3443/meeting-service/ui`，输入管理员令牌后查看会议、转写和纪要，下载录音，重试失败任务或确认删除服务端会议。验证成功后，页面将管理员令牌缓存于当前浏览器，7 天后过期；刷新页面会恢复未过期的令牌。浏览器需信任服务证书并且证书主机名匹配。已使用模拟数据检查页面交互及响应式布局，并用真实测试会议验证编辑、刷新和下载；尚未完成完整无障碍及真实会议质量验收。

长转写分批的有效结果会临时保存在数据库中，带转写版本、模型标识和实际提示内容的哈希；处理失败或重启后可复用已完成的批次。结果提交、重新转写和会议删除时会清理这些中间结果。模型调用仍可能在服务崩溃前已计费而结果未保存，不能保证外部调用恰好一次。

真实服务验证脚本：设置 `STEPFUN_API_KEY` 后，在 `server/` 目录运行 `node src/live-workflow.mjs ../test-audio/distance-03.opus`。脚本会将所选录音发送给 StepFun，调用 ASR 和纪要模型，可能产生费用；该示例的字符错误率以此前的 0.3 米标准朗读文本为参考，其他录音的这个指标不适用。它只输出指标和计数，不打印密钥或逐字稿，结束后删除临时数据库；异常终止时应检查系统临时目录是否残留 `meeting-live-*`。模型供应商及其日志的处理不由本脚本控制。

服务启动要求 `MEETING_DATA_DIR` 及已有数据库文件和 SQLite 附属文件由当前用户持有，且不允许组或其他用户访问；进程以 `umask 077` 创建新文件。若已有目录权限不符合要求，启动会报错，需要管理员确认后修正。权限位检查不能替代对文件系统 ACL、备份和主机安全的检查。

2026-10-30：此前授权的 0.3 米短录音已通过本服务、真实 StepFun ASR 与 agent-runtime 纪要链路；参考文本字符错误率约 7.3%。引用位置通过校验，但语义准确性和真实会议表现尚未验收。

在默认 HTTPS 模式下，启动时会验证 TLS 证书的有效期及其与私钥的匹配；HTTP 模式由受信任的反向代理终止 TLS。端口须为 1–65535 的整数，只有监听成功后才启动后台队列；若端口被占用，服务退出且不会开始处理录音。客户端仍必须验证证书链和主机名，启动检查不代替客户端验证。

关闭服务时，停止接受新业务请求，并等待现有连接最多 10 秒；超时后断开连接、中止未完成请求并等待业务处理退出，再关闭数据库。设备必须将连接中断或超时视为结果未知，重新查询并核对完整清单后才能删除本地副本。服务器的请求头、请求和空闲连接分别设有 15 秒、30 秒和 5 秒超时；部署在反向代理后仍需配置代理侧超时与限流。

对已有的三段不同合成标记样本，可在上面的真实服务验证命令中将音频路径替换为该样本并追加 `--distinct-markers`。输出的三个布尔值和顺序标志用于判断标记是否出现；标记缺失或顺序不符时脚本返回失败状态和非零退出码；成功也不保证纪要语义正确。

后台默认最多并发处理两场会议；可通过 `MEETING_WORKER_CONCURRENCY` 设置 1–4，管理员可通过设置接口查看。并发可避免单个缓慢模型请求完全阻塞其他会议；外部模型调用可能并行产生费用和更高内存占用。并发受单进程限制，不是跨实例协调或吞吐量保证。

真实服务验证脚本支持追加 `--no-reference`：对没有标准参考文本的样本只输出逐字稿字符数和增量事件数，不计算错误率或打印正文。此前授权的 30 分钟设备录音曾因引用摘录不匹配而无法发布纪要；调整为由服务端附加原文范围后，同一录音的一次完整链路测试通过了引用定位与格式检查。该次未人工核对语义，详见验收追踪。

`node src/live-worker-eval.mjs` 使用标准输入读取密钥，以虚构文本通过实际工作器调用纪要模型，并检查三个语义反例；最多尝试三次，测试会跳过重试等待，可能产生费用。结果仅为小样本，不代表真实会议质量。

会议详情支持创建临时只读分享链接：纪要必选，逐字稿及下载权限可选且默认关闭，有效期默认 7 天（1–365 天）。链接持有者无需管理员令牌即可访问，分享页显示人工复核提示；重新转写期间暂不可用，完成后展示最新版本。链接包含访问凭证，应妥善发送；请使用接收者可访问的 HTTPS 地址，localhost 无法供远程访问。会议删除后新访问失效，尚在读取中的响应可能完成。无单独撤销功能；服务器时钟回拨可能延长实际有效期。恢复和降级的分享状态限制见 BACKUP.md。

外部服务可申请会议纪要订阅，管理员批准后，每次新纪要完成都会收到自动生成的只读分享链接。管理页右上角“订阅管理”支持查看申请和投递状态、批准、拒绝及撤销。管理员可在审批时配置有效期（默认 7 天）、是否包含逐字稿和是否允许下载，批准后也可修改；修改只影响之后生成的链接。订阅不会补发批准前的历史会议，重新转写完成会产生新事件。回调失败会持久化重试，接收方须按事件 ID 去重。启用推送须将 `MEETING_PUBLIC_BASE_URL` 配置为外部可访问的服务地址并包含挂载路径，例如 `https://meetings.example.com/meeting-service`；未配置时申请和审核仍可使用，但不会执行回调。接口及回调格式见 API.md。
